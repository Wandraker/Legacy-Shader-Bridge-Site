Future directionБудущее направление

Native LSB should expose the renderer without legacy-era constraints.Native LSB должен открывать renderer без legacy-era ограничений.

The native shader API does not exist yet. This page documents only the architectural direction that is stable enough to say now.Нативного shader API пока не существует. Эта страница фиксирует только то архитектурное направление, которое уже достаточно устойчиво, чтобы его описывать.

The next frontend, not a second rendererСледующий frontend, а не второй renderer

The planned native API should sit above the same renderer core that the legacy frontend is forcing into shape today. The point is to expose renderer capabilities directly, not to duplicate scene submission, lifetime tracking or Vulkan execution in a separate system.Запланированный native API должен находиться над тем же renderer core, который сегодня формируется через legacy frontend. Смысл — напрямую открыть возможности renderer-а, а не дублировать scene submission, lifetime tracking или Vulkan execution во второй системе.

Direction that is already clearЧто уже понятно о направлении

  • explicit render targets and formats where useful;явные render targets и formats там, где это полезно;
  • explicit pass dependencies and resource ownership;явные зависимости pass'ов и resource ownership;
  • compute workloads, storage resources and temporal lifetimes without legacy naming tricks;compute workloads, storage resources и temporal lifetime без legacy naming tricks;
  • a versioned public contract instead of exposing accidental internal implementation details.versioned public contract вместо раскрытия случайных внутренних implementation details.

What is deliberately not frozenЧто намеренно не фиксируется

File layout, shader syntax, resource declaration syntax and scheduling syntax remain undecided. Freezing them before the renderer fundamentals are stable would turn today's temporary implementation into tomorrow's compatibility burden.File layout, shader syntax, syntax resource declarations и scheduling syntax остаются нерешёнными. Если зафиксировать их до стабилизации renderer fundamentals, сегодняшняя временная реализация станет завтрашним compatibility-бременем.
