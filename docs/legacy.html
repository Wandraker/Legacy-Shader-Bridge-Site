CompatibilityСовместимость

Legacy is the first frontend, not the ceiling of the renderer.Legacy — первый frontend, а не потолок renderer-а.

The compatibility frontend exists to make real existing shader packs work truthfully on the renderer. It is a translation and validation layer, not the final public API.Compatibility frontend нужен, чтобы реальные существующие shader pack'и честно работали на renderer-е. Это слой перевода и проверки, а не конечный публичный API.

Compatibility is a reconstruction processCompatibility — это процесс реконструкции

The legacy frontend has to discover what the pack expects, map those expectations onto renderer-level resources and state, and then validate that the required producers actually exist. Translation without that validation would only move incorrect assumptions into Vulkan.Legacy frontend должен определить, чего ожидает pack, сопоставить эти ожидания с renderer-level ресурсами и state, а затем проверить, что нужные producers реально существуют. Перевод без такой проверки просто перенёс бы неправильные предположения в Vulkan.

Fail-closed behaviorFail-closed поведение

When a path lacks required geometry, attachment contents, bindings or producer state, LSB should keep that path closed. This is intentionally stricter than producing a plausible image with fabricated inputs, because a visually convincing result can still violate the shader pack's actual contract.Когда пути не хватает нужной геометрии, attachment contents, bindings или producer state, LSB должен оставить этот path закрытым. Это намеренно строже, чем выдавать правдоподобную картинку на выдуманных inputs, потому что визуально убедительный результат всё равно может нарушать реальный контракт shader pack.

Why Photon is usedПочему используется Photon

Photon is useful because its multi-pass pipeline stresses shadows, deferred/composite work, temporal resources, scene geometry and attachment lifetimes at the same time. It is a development workload that exposes problems efficiently, not a special-case API target and not the final scope of compatibility.Photon полезен потому, что его multi-pass pipeline одновременно нагружает shadows, deferred/composite work, temporal resources, scene geometry и lifetime attachments. Это development workload, который эффективно вскрывает проблемы, а не специальная API-цель и не конечная граница compatibility.
