Core architectureАрхитектура

Passes only make sense together with their resources and dependencies.Pass'ы имеют смысл только вместе с ресурсами и зависимостями.

LSB converts a pack-defined multi-stage pipeline into ordered native work while preserving the data relationships between scene submission, attachments and later consumers.LSB превращает pack-defined multi-stage pipeline в упорядоченную нативную работу, сохраняя связи данных между scene submission, attachments и поздними consumer-ами.

Execution is ordered work, not a list of shadersExecution — это упорядоченная работа, а не список shader-ов

A real shader-pack pipeline is a dependency chain. Earlier stages produce attachments or temporal state that later stages consume. LSB has to preserve that relationship while translating it into explicit Vulkan resource ownership and synchronization.Реальный shader-pack pipeline — это цепочка зависимостей. Ранние стадии производят attachments или temporal state, которые потребляют поздние стадии. LSB должен сохранить эту связь, переводя её в явный Vulkan resource ownership и synchronization.

Simplified legacy-style execution flowУпрощённый legacy-style execution flow
The exact stage set is pack-dependent. This diagram shows the dependency model, not a promise that every pack has exactly these four stages.Точный набор стадий зависит от pack-а. Схема показывает модель зависимостей, а не обещает, что каждый pack содержит ровно эти четыре стадии.

Scene work and post-processing are connectedScene work и post-processing связаны

Terrain, entities, block entities, particles, hand rendering and translucent surfaces feed scene data into the pipeline. Later passes can only be correct if the geometry, depth and attachment producers before them were correct.Terrain, entities, block entities, particles, hand rendering и translucent surfaces подают данные сцены в pipeline. Поздние pass'ы могут быть корректны только если геометрия, depth и producers attachments до них были корректны.

Temporal resources have lifetimeTemporal resources имеют lifetime

History buffers and previous-frame state are not ordinary scratch data. Their identity and lifetime cross frame boundaries, so LSB treats them as explicit renderer resources rather than accidental leftovers from the previous frame.History buffers и previous-frame state — не обычные временные данные. Их identity и lifetime пересекают границы кадров, поэтому LSB рассматривает их как явные renderer resources, а не случайные остатки прошлого frame.
